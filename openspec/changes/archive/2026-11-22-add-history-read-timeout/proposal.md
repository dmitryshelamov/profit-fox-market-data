# Proposal

## Why

2026-11-22 прогон H0001 стенда упал на 485-й паре из 831: один запрос истории свечей ждал Postgres 33 с, а у Npgsql таймаут
команды по умолчанию 30 с. Обычный запрос части окна (64 дня одной пары) идёт 0,1–0,4 с; за прогон из 1885 вызовов три шли
18, 24 и 33 с — в те часы догрузка buy volume переписывала сжатые чанки свечей. Таймаут сейчас нигде не задан и одинаков для
чтения истории и для записи; потребитель получает `UNKNOWN` «Exception was thrown by handler.» и не может отличить
временный сбой хранилища от ошибки.

## What Changes

- Новая настройка `HistoryRead:StatementTimeoutSeconds` (по умолчанию `120`): сколько каждый запрос к хранилищу при чтении
  истории (`History` всех лент: проверка инструментов, покрытие, части строк) может ждать Postgres. Читается в начале каждого
  вызова, так что правка `config/market-data.json` на сервере действует со следующего вызова без перезапуска.
- Таймаут команд записи и остальных запросов (REST, ленты, фоновые службы) не меняется: он остаётся из строки подключения.
- Значение не больше нуля: приложение с ним MUST NOT стартовать; сломанная правка на ходу пишется в журнал один раз, и чтения
  идут с последними верными настройками секции `HistoryRead` — так же, как у настроек API бирж.
- Запрос истории, не дождавшийся хранилища, завершает вызов с `UNAVAILABLE` и понятным текстом вместо `UNKNOWN`: потребитель
  повторяет чтение.

### Modified Capabilities

- `history-stream`: новые требования «Ожидание хранилища» (таймаут запросов истории как настройка на ходу) и «Хранилище не
  ответило вовремя» (`UNAVAILABLE`); требование «Одновременные чтения» получает сохранение последних верных настроек при
  сломанной правке.

## Impact

- `ProfitFox.MarketData.Presentation`: `HistoryReadSettings` (новое свойство), регистрация секции в `Program.cs`,
  `HistoryCall` (статус при таймауте), `appsettings.json`.
- `ProfitFox.MarketData.Infrastructure`: обработчики `History` и покрытия четырёх лент, `HistoryRows`,
  `HistoryCoverageReader`, `HistoryConnection` — таймаут команды на каждый запрос.
- `ProfitFox.MarketData.Application`: исключение «хранилище не ответило вовремя».
- gRPC-контракт не меняется; меняется только статус ответа при таймауте (`UNKNOWN` → `UNAVAILABLE`).
- Выкладка: новый релиз на soyo-02; после неё таймаут правится в `config/market-data.json`.
